## 装備製作を読む順序

**完成装備が保持する通常アレンジは3枠です。製作画面の投入可能な6枠とは別です。** 必須素材はレシピ成立に必要な品、追加素材は空き枠へ加える品です。追加した品だけでなく、必須素材や投入装備に由来する情報も、この3枠に関わります。

<h2 id="auto-trigger">オートアレンジ：必須素材由来の候補</h2>

既存の内部アレンジがない通常製作では、必須素材4個なら1個、5個なら2個が必須素材から自動選出されます。3個以下なら0個です。一方、性能継承時に既存内部アレンジ等で枠が満たされる場合は、ベース装備由来の新しいオートアレンジが混入しない挙動が観測されています。**生成数の基本条件と、継承時の混入条件を分けます。**

{% include rf/auto-basics.html %}

<h2 id="internal-arrange">内部アレンジは保持され、次の製作へ関わる</h2>

オートアレンジは生成時だけの一時的な情報ではありません。一度完成装備の内部アレンジとして確定すると、その装備に保持され、後続製作で参照対象になります。内部アレンジは完成装備が保持する情報を指す本サイトの説明用語で、オートアレンジと同義ではありません。

{% include rf/persistence.html %}

生成時には既存の継承情報よりオートアレンジの優先度が低いと考えられます。しかし、すでに内部アレンジとして確定した情報は、後の製作で追加アレンジ等と同じ候補集合で競合し得ます。**生成時の優先度と、確定後の候補としての扱いは別です。** 確定後の等優先性は観測に基づく解釈であり、同じ内部重み・処理が使われると断定するものではありません。

<h2 id="equipment-body">装備本体候補化：中身とは別に本体も参加する</h2>

靴・アクセサリー継承の観測では、投入した同カテゴリ装備の本体も候補になります。内部アレンジA・B・Cを持つ靴なら、本体も加わることで4候補が3枠を取り合う説明ができます。

<div class="auto-figure"><h3>他の候補がない条件での説明モデル</h3><div class="tokens"><span class="token">内部A</span><span class="token">内部B</span><span class="token">内部C</span><span class="token noise">靴本体</span></div><p><strong>4候補 → 保持3枠</strong>。本体と内部情報は別の由来です。本体が現れたことだけで内部参照まで証明したことにはなりません。</p></div>

装備本体が候補になること、内部アレンジが参照されること、性能・特殊効果が継承されることも、それぞれ分けて確認します。全カテゴリ・全レシピへ一律に適用する説明ではありません。

## 第一同カテゴリ内部アレンジ参照

**観測上の条件付き規則**：試験された条件では、同カテゴリ装備の投入順と、後で参照される内部アレンジとの対応が確認されています。「第一」は入力順と結果の対応を表します。内部で先頭一致を走査する実装や再帰展開が確認された意味ではありません。

### 候補生成と候補選択を分ける

1. 通常レシピ・追加素材・投入装備の内部状態を記録する。
2. 結果へ関与する候補を、観測の範囲で整理する。
3. 候補が3枠を超える条件で、何が残るかを別に調べる。

オートアレンジはレシピ由来の候補、装備本体候補化は投入装備そのもの、内部参照は保持された情報に関する観測です。内部参照の観測だけで全条件の候補数Nを確定することはできません。上の4候補例は、記載した内部状態と他の候補が発生しない条件を置いた説明モデルです。

[3製法の使い分け](method-comparison.html)では、この規則を製作に応用する方法を整理します。


<h2 id="hidden-x">見えない不要候補X：出所が違っても3枠を取り合う</h2>

メッシライト継承では、グリッタ輝石3個だけを目的としていても、メッシライト鉱石をXとする4候補モデルで競合を考えます。靴・アクセサリーでは、意図しない内部アレンジや本体がXになり得ます。Xは固有の素材名ではなく、今回の目的から外れる候補を表す記号です。

{% include rf/hidden-x.html %}

4候補から3候補を**等確率・非復元で選ぶモデル**では、Xが残る組合せは3通り、Xを避ける組合せは1通りです。メッシライト鉱石の混入確率は3/4＝75%、回避確率は1/4＝25%。RF5の[3積み1,000回の成功率25.0%](rf5-4000-trials.html)と整合しますが、内部抽選アルゴリズムの証明ではありません。RF4SPの実際の混入・回避確率にはこの値を当てはめません。

### 自分が狙わなかった候補は、どこから？

| 着目する現象 | 研究資料での整理 | 混同しない点 |
|---|---|---|
| オートアレンジ | レシピの必須素材が候補に関わる場合がある | 既存装備の内部アレンジ参照とは別 |
| 装備本体候補化 | 投入装備そのものが結果に現れる挙動 | 本体が現れても、内部まで展開した証拠にはならない |
| 内部アレンジ参照 | 装備に保持された情報が後の製作結果に現れる | 内部の候補登録・走査順序は別途検証が必要 |


<h2 id="work-selection">候補数が同じでも、作品で抽選特性は異なる</h2>

|項目|RF4SP|RF5|
|---|---|---|
|候補数管理|研究上有用|研究上有用|
|等確率モデル|一般適用不可|対象条件で実測と整合|
|素材ごとの選択偏り|観測あり|一般化未確定|
|排列位置の偏り|観測あり|一般化未確定|
|オートアレンジ生成時の重み|有力な研究仮説|未確定|

候補の出所を整理することと、そこから選ぶ確率を決めることは別です。[RF4SPの選択・排列研究](rf4sp-selection-bias.html)と[RF5の4,000回検証](rf5-4000-trials.html)を区別し、[RF5用計算器](candidate-count-calculator.html)をRF4SPの攻略成功率へ適用しないでください。

## プレイヤーには何が役立つ？

「失敗したら作り直す」の前に、通常レシピ、追加した装備、装備が保持するアレンジを分けて確認できます。クッション製法とダミー製法は、こうした<strong>製作前の条件</strong>を工夫する研究製法です。

<div class="callout"><p><strong>鑑定表示と、特殊効果の発現も分けます。</strong><br>目的の装備名が表示されたことだけで、すべての特殊効果が発現したとは判断しません。</p></div>


{% include rf/method-controls.html %}

[クッション製法](cushion-method.html#候補集合を変える原理)は参照対象を空の装備へ切り替え、候補集合そのものを変えます。[ゴーストロケットの実践](practical-equipment.html)では、この原理と投入枠の条件を合わせて確認できます。ダミー・シャッフルも、候補数だけでなく種類・内部状態・順序を工夫する製法です。

<h2 id="auto-boundary">RF5：オートアレンジ混入の境界値テスト</h2>

ベース装備（原図の表記は「作成枠4」）、性能継承元、追加素材の超栄水という構成で、最終合成後に鍛冶屋でアレンジ枠を鑑定した観測です。超栄水は識別用の追加素材として使われています。

{% include rf/auto-boundary.html %}

各条件は<strong>1試行</strong>です。既存攻略資料が示すアレンジ継承の優先と整合する結果です。Aで混入しB・Cで混入しなかったという観測は、アレンジ枠が不足する条件で補完由来の候補が関わり、枠が埋まるとその優先度が低くなる可能性と整合します。B・Cの非混入は、候補が生成されなかったことや、その確率が0であることの証明ではありません。内部登録順・選択順・優先順位を確定するには追加試験が必要です。

<h2 id="auto-rf4-hypothesis">RF4SP：重みが働く段階を分ける</h2>

**筆者の研究仮説では、RF4SPはオートアレンジ自体にも素材依存の重みが存在する可能性が高いと考えています。** ただし、どの段階に重みがあるかは未確定です。

|区別する段階|検討する偏り|現在の読み方|
|---|---|---|
|オートアレンジ生成|必須素材ごとの選出優先度|生成段階にも重みがあるという研究仮説|
|内部参照・候補生成|保持情報・本体が候補へ関わる条件|候補の出所を整理する段階。内部実行順は未確定|
|継承候補の選択|候補ごとの選出優先度|4候補から3候補を残す検証と対応させて検討|
|最終排列|素材ごとの排列位置|3候補の位置集計と対応させて検討|

自動生成・候補選択・排列の偏りが同一の重みで制御されるとは限りません。生成段階で偏れば後続の選択が等確率でも結果に偏り得ます。逆に、生成は等確率で後続だけに重みがある可能性もあります。[排列位置と候補選択の検証](rf4sp-selection-bias.html)は、オートアレンジ生成時の重みの直接証明ではありません。段階の区別は分析上の整理で、内部の実行順を確定するものでもありません。

RF4SPで候補数を管理する考え方は有用ですが、[RF5向け等確率計算器](candidate-count-calculator.html)をRF4SPの攻略成功率へ直接適用できません。

## 既存攻略知識と研究モデルの出典

生成数とアレンジ継承の優先は、[RF4攻略Wiki](https://wikiwiki.jp/rune4/強化)・[RF4 Wiki](https://wikiwiki.jp/rf4/強化)・[RF5攻略Wiki](https://wikiwiki.jp/rf5/強化)、RF4SPの[いたちと気ままなゲームびより](https://choconasubi.com/?p=2641)、RF5の[ゆいのゲーム日記](https://yuigame.com/2021/06/15/rune-factory-5-arrangement-inheritance-and-auto-arrangement-commentary/)でも説明されています。コミュニティ攻略資料であり、公式仕様書や内部コードの証拠ではありません。記載の一致だけで、互いに独立した検証を行ったことまでは保証しません。

図A・B・Gと境界値テストは筆者の[研究投稿](https://x.com/AJ1B5OznFS44920/status/2075148633347932336)の説明をWeb向けに再構成しています。「ランダム」と「等確率」は同義ではありません。RF5の[4,000回検証](rf5-4000-trials.html)と等確率・非復元モデルの整合は特定の候補選択条件についての結果で、オートアレンジ生成自体まで等確率と確定した意味ではありません。

### 等確率と重み付きという考え方

<div class="auto-panels auto-figure"><div><h4>等確率という仮定</h4><p>候補ごとの選ばれやすさを同じと置くモデル。</p></div><div><h4>重み付きという仮説</h4><p>候補ごとに選ばれやすさが異なる可能性を扱う。重みは未確定。</p></div></div>

この比較は考え方の図解です。RF4SPの実測分布や具体的な重みを表すものではなく、重み付き確率計算器も提供しません。

### 入手経路も今後の確認条件にする

RF4攻略Wikiには、店舗購入やバドからのお返しで得た装備にはオートアレンジが付いていないとの記載があります。内部アレンジのない装備を選ぶ方法を考える際の参考ですが、RF4無印の記載をRF4SP・RF5へ自動適用はしません。各作品で入手経路と鑑定結果を確認する研究課題です。
